# G5真实性能验证

测试日期2026-11-06。仅本机合成数据、闭环HTTP读取实验，不是生产容量或写入TPS认证。所有正式轮次保留；没有取最佳轮替代整体。

## 环境与数据

Windows11 10.0.26100，i7-14650HX，24逻辑核心，约16GB物理内存，平衡电源；开始可用内存约2.8—3.9GiB。JDK21.0.7，MySQL8.4.13，buffer pool128MiB，max_connections30；一个后端，-Xms128m/-Xmx384m，Hikari10，任务池2线程/SynchronousQueue。Python3.13.2标准库HTTP客户端与测试类路径JDBC计时，Chrome不参与基准。测试期间不并行执行JUnit/npm构建。

合成读取夹具分级实际生成1万、5万、10万订单。最终基础读取集：10000名普通合成用户+3管理/技师+1 SYSTEM，1000型号，100000订单，2857故障/工单，21429归还申请，142857库存日志，100000导入命令，242857事件，10000任务。用户1001拥有1万订单，包含热点用户；订单7态分布，业务时间范围2025年，按型号计数而非逐台资产。

读取批量导入明确标为SYNTHETIC_SEED/SNAPSHOT，不能作为真实Service正确性证明。另400笔订单通过真实Service创建，分别形成真实任务、ALLOCATE/RELEASE和SYSTEM审计，全部取消收敛。最终perf为100400订单、1001型号。

基础数据v1用于两组索引矩阵和任务比较；之后修正仅导入夹具的actor关联及历史未支付任务语义，形成v2，数量/库存未变。具体修正见bulk-fixture-correction.json；不把v2发布查询与v1矩阵混为同一实验。

夹具仍有时间简化：订单created_time按2025年分布，但租期、维修派工与部分导入任务时间使用固定2025年常量，未逐条构造业务发生顺序。关联/状态分布/库存守恒已核对；这不等于10万条真实履约轨迹。该局限不影响本轮按created_time分页/索引对照，但不能用于时间合规或任务时效证明；真实时间和状态转换以Service队列与完整业务Gold为准。未改写既有测量数据来隐藏这一点。

## 公平对照

G4原业务读取源码保持，初始测量提交575d5739245119e3aac1ab15b01f2b7f4b141a4d；V6索引对照提交80a2f82b85697448fe07324bc7a3d7bbe219ef00。两组使用相同安全补丁前依赖、相同数据和测量器、同一MySQL实例，未改变事务、权限、SQL返回、排序或分页上限。之后安全补丁版本另测，不将补丁收益归给索引。

V6增加owner/state、global/time、state/time及assignee/time共4个非唯一索引。V1—V5不改；未引入缓存或去掉COUNT/权限。索引有写入与存储成本，没有在本实验中声称写吞吐提升。

10类真实已认证GET混合：本人订单/状态筛选、管理员订单/状态筛选、本人技师工单/状态筛选、管理员维修、订单详情、时间线、任务。固定pageSize20，localhost，客户端无思考时间，每连接复用HTTP；登录BCrypt成本不在测量内，但JWT签名验证和数据库当前角色读取在内。

每并发预热30秒，再3轮各60秒；实际时长和每轮请求数在原始摘要中。并发1/10/30，所有正式成功率100%，非预期500=0，预期409=0（读取场景）。

## 没有解决或不能归因的部分

深OFFSET第1000页100行实测约0.7秒，仍需跳过大量行；包含式LIKE也没有自动获得B-tree前缀定位能力，扫描近万行。原始样本和计划见remaining-query-limits.json；本轮不新增搜索引擎、全表缓存或重写分页协议。详情/审计等未直接使用新增索引的接口，端到端波动不能全部归因索引。

任务关闭/开启各3轮使用同一最终安全补丁、相同3类核心查询和400笔到期Service任务。轮间波动明显，不能据此估计纯Worker开销，也不把开启组某轮更快解释成任务提升性能。可以确认：全部请求200、无连接超时、等待快照≤2，400任务最终DONE/CANCELLED、stock50→450、每单一次RELEASE、无持续积压。不是长期稳定性测试。

## 失败、采样限制及复现

首个客户端把审计Event当订单校验，产生10%伪失败；整次中止并保留load-invalid-client-oracle，不纳入正式统计。修正后完整重跑，不是删除服务错误。before的MySQL CPU误采启动父进程，字段无效，不能把0当MySQL无负载；Java CPU及内存有效，后续修正监听子进程。死锁计数自本实例启动为0，读阶段行锁等待0。池等待为响应结束快照，不是持续采样峰值。

初次性能启动器使用Flyway未填充的getUrl失败，改为连接元数据验证后成功；只影响test-classpath工具。批量读取夹具的actor/历史任务语义问题已在所有成对测量之后修正，真实400笔Service Gold未受影响。旧Gold断言不改。

原始CSV.gz逐请求含接口、状态、HTTP/JDBC/装配/checkout/等待快照；完整保留于本机开发证据，公开候选提供每轮原始摘要、文件SHA及重现脚本，排除大量重复施工证据。硬件、电源/缓存/JIT、同机客户端及其他桌面活动限制外推；不宣称万个并发或生产TPS。
